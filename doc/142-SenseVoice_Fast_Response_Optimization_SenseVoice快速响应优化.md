# SenseVoice快速响应优化 - 渐进式策略

## 问题

之前的优化虽然提高了识别准确率，但导致等待时间过长（0.8秒），技能执行太慢，用户体验不佳。

## 优化策略

采用**渐进式快速响应策略**：
- 🚀 **首次识别**：快速反馈（0.5秒）→ 让用户知道系统在工作
- 🎯 **后续识别**：提高质量（0.7秒）→ 确保识别准确率
- ⚡ **快速结束**：有结果后1.2秒超时 → 减少等待时间

## 详细优化点

### 1. 渐进式音频时长要求 📏

```kotlin
// 优化前：统一要求0.8秒
private val PARTIAL_MIN_AUDIO_DURATION_SEC = 0.8f

// 优化后：渐进式策略
private val PARTIAL_FIRST_MIN_AUDIO_DURATION_SEC = 0.5f  // 首次：0.5秒
private val PARTIAL_NORMAL_MIN_AUDIO_DURATION_SEC = 0.7f // 后续：0.7秒
private var partialRecognitionCount = 0 // 识别次数计数
```

**实现逻辑**：
```kotlin
val minAudioDuration = if (partialRecognitionCount == 0) {
    PARTIAL_FIRST_MIN_AUDIO_DURATION_SEC // 首次：快速响应
} else {
    PARTIAL_NORMAL_MIN_AUDIO_DURATION_SEC // 后续：提高准确率
}
```

**效果**：
- ✅ 首次识别时间：0.5秒（比之前快37.5%）
- ✅ 给用户即时反馈，感知系统正在工作
- ✅ 后续识别保持较高准确率

---

### 2. 缩短识别间隔 ⏱️

```kotlin
// 优化前
private val PARTIAL_RECOGNITION_COOLDOWN_MS = 500L

// 优化后
private val PARTIAL_RECOGNITION_COOLDOWN_MS = 400L
```

**效果**：
- ✅ 更频繁地更新识别结果
- ✅ 渐进式显示更流畅

---

### 3. 优化静音超时 - 三级策略 ⚡

```kotlin
// 优化前：固定1.8秒
return if (partialText.length >= 3) {
    1800L
} else {
    SPEECH_TIMEOUT_MS // 4秒
}

// 优化后：三级动态超时
return if (partialText.length >= 3) {
    1200L  // 有完整识别（≥3字符）：1.2秒超时（快速响应）
} else if (partialText.length >= 1) {
    1800L  // 有部分识别（≥1字符）：1.8秒超时（中等响应）
} else {
    SPEECH_TIMEOUT_MS  // 无识别结果：4秒超时（耐心等待）
}
```

**三级超时策略**：

| 识别状态 | 超时时间 | 使用场景 |
|---------|---------|---------|
| 完整识别（≥3字符） | 1.2秒 | "유튜브" → 快速执行命令 |
| 部分识别（≥1字符） | 1.8秒 | "유" → 继续等待补全 |
| 无识别 | 4.0秒 | 静音或背景噪音 → 耐心等待 |

**效果**：
- ✅ 有明确命令后快速结束（1.2秒）
- ✅ 减少用户等待时间33%（从1.8秒降到1.2秒）
- ✅ 提高技能执行速度

## 技术权衡

### 首次识别（0.5秒）
- ✅ **优点**：快速反馈，用户感知好
- ⚠️ **风险**：可能输出"."等无意义结果
- 🛡️ **防护**：音频质量检查 + 内容过滤

### 后续识别（0.7秒）
- ✅ **优点**：准确率高，识别质量好
- ⚠️ **权衡**：比首次慢0.2秒
- 💡 **理由**：用户已有初步反馈，可接受稍慢

### 快速超时（1.2秒）
- ✅ **优点**：命令执行快
- ⚠️ **风险**：可能截断长句子
- 🛡️ **防护**：仅在识别≥3字符时启用
