# 开机自启动与系统应用权限配置指南

本文档总结应用的开机自启动实现方案、系统应用（system uid）配置、默认权限授予方式，以及各版本 Android 的限制与注意事项，便于集成与验证。

## 1. 目标与原则
- 设备重启后自动拉起应用的悬浮窗 UI 服务，实现“看得见的运行态”。
- 避免在开机广播阶段直接启用麦克风前台服务，满足 Android 11+ 的隐私限制。
- 在用户解锁后自动启动唤醒麦克风服务，实现“无点击恢复语音能力”。
- 作为系统应用运行，预置默认权限，减少用户交互。

## 2. 实现策略概览
- 开机阶段（`BOOT_COMPLETED`/`LOCKED_BOOT_COMPLETED`）：仅启动不含麦克风类型的前台 UI 服务（`EnhancedFloatingWindowService`）。
- 用户解锁（`USER_PRESENT`）：检测权限与唤醒状态，自动启动麦克风前台服务（`WakeService`）。
- Manifest 中为接收器启用 `android:directBootAware="true"`，同时监听 `LOCKED_BOOT_COMPLETED`、`BOOT_COMPLETED` 与 `USER_PRESENT`。
- 悬浮窗服务移除麦克风前台类型标注；麦克风服务保留前台类型标注。

## 3. Manifest 配置要点

### 3.1 顶层与权限声明
```xml
<manifest
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    android:installLocation="auto"
    android:sharedUserId="android.uid.system">

    <!-- 覆盖三方库 minSdkVersion 检查（示例） -->
    <uses-sdk tools:overrideLibrary="com.ifpdos.sdklib.hyundaiit" />

    <!-- 基础权限与前台服务类型（按需精简） -->
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.RECORD_AUDIO" />
    <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_MICROPHONE" />
    <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
    <uses-permission android:name="android.permission.USE_FULL_SCREEN_INTENT" />
    <uses-permission android:name="android.permission.QUERY_ALL_PACKAGES"
        tools:ignore="QueryAllPackagesPermission" />

    <!-- 悬浮窗权限（注意：AppOps 管控，需设备侧默认允许） -->
    <uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
```

### 3.2 开机接收器（支持未解锁）
```xml
<receiver
    android:name=".io.wake.BootBroadcastReceiver"
    android:exported="true"
    android:directBootAware="true">
    <intent-filter>
        <category android:name="android.intent.category.DEFAULT"/>
        <action android:name="android.intent.action.LOCKED_BOOT_COMPLETED" />
        <action android:name="android.intent.action.BOOT_COMPLETED" />
        <action android:name="android.intent.action.USER_PRESENT" />
        <action android:name="android.intent.action.QUICKBOOT_POWERON"/>
        <action android:name="com.htc.intent.action.QUICKBOOT_POWERON"/>
    </intent-filter>
</receiver>
```

### 3.3 服务声明
```xml
<!-- 保留麦克风类型的前台服务（语音唤醒/录音） -->
<service
    android:name=".io.wake.WakeService"
    android:enabled="true"
    android:exported="false"
    android:foregroundServiceType="microphone"
    android:icon="@mipmap/ic_launcher"
    android:label="@string/wake_service_label" />

<!-- 悬浮窗服务：不标注麦克风类型，避免开机阶段受限 -->
<service
    android:name=".ui.floating.EnhancedFloatingWindowService"
    android:enabled="true"
    android:exported="false"
    android:label="Enhanced Floating Assistant" />

<!-- STT 识别服务（如需） -->
<service
    android:name=".io.input.stt_service.SttService"
    android:description="@string/stt_service_label"
    android:directBootAware="true"
    android:exported="true"
    android:foregroundServiceType="microphone"
    android:icon="@mipmap/ic_launcher"
    android:label="@string/stt_service_label"
    android:permission="android.permission.RECORD_AUDIO" />
```

## 4. 关键代码逻辑

### 4.1 `BootBroadcastReceiver`
```kotlin
override fun onReceive(context: Context, intent: Intent) {
    // 开机/锁定开机：仅启动悬浮窗，不触碰麦克风
    if (intent.action == Intent.ACTION_BOOT_COMPLETED ||
        intent.action == Intent.ACTION_LOCKED_BOOT_COMPLETED ||
        intent.action == "android.intent.action.QUICKBOOT_POWERON" ||
        intent.action == "com.htc.intent.action.QUICKBOOT_POWERON") {
        if (Settings.canDrawOverlays(context)) {
            EnhancedFloatingWindowService.start(context)
        }
    }

    // 用户解锁：若已授予录音权限且唤醒词启用，启动 WakeService（麦克风前台服务）
    if (intent.action == Intent.ACTION_USER_PRESENT) {
        if (ContextCompat.checkSelfPermission(context, RECORD_AUDIO) ==
            PackageManager.PERMISSION_GRANTED) {
            WakeService.start(context)
        }
    }
}
```

### 4.2 `EnhancedFloatingWindowService`
- 前台通知：使用 `startForeground(NOTIFICATION_ID, notification)`，不传入麦克风类型常量。
- 仅在 Android 10 及以下于服务内部启动 `WakeService`；Android 11+ 由解锁广播触发。

## 5. 系统应用（system uid）与默认授权

### 5.1 system uid
- 在 Manifest 顶层添加：`android:sharedUserId="android.uid.system"`。
- 使用设备“平台密钥”签名，作为特权系统应用部署到 `/system/priv-app/`。
- 变更 `sharedUserId` 风险大：与已安装版本签名不一致会导致 `INSTALL_FAILED_SHARED_USER_INCOMPATIBLE`，需卸载旧版并清数据。
- 说明：Android 10 起官方不再推荐普通应用使用 `sharedUserId`，系统集成场景下仍可工作。

### 5.2 权限白名单与默认授予
- `privapp-permissions`（签名/特权权限）：
```xml
<permissions>
  <privapp-permissions package="com.ai.voice">
    <permission name="android.permission.RECEIVE_BOOT_COMPLETED"/>
    <permission name="android.permission.FOREGROUND_SERVICE"/>
    <permission name="android.permission.FOREGROUND_SERVICE_MICROPHONE"/>
    <permission name="android.permission.QUERY_ALL_PACKAGES"/>
    <!-- SYSTEM_ALERT_WINDOW 为 AppOps 管控，需单独处理，见下文 -->
  </privapp-permissions>
</permissions>
```
- 危险权限（运行时，如 `RECORD_AUDIO`、`POST_NOTIFICATIONS`）默认授予：
  - 建议通过 OEM 的 `default-permissions` 机制或设备策略（DPM）进行默认 grant；
  - 或在初始化脚本中执行 `pm grant com.ai.voice android.permission.RECORD_AUDIO`（需系统权限）。
- 悬浮窗（`SYSTEM_ALERT_WINDOW`）默认允许：
  - 属于 AppOps：`adb shell appops set com.ai.voice SYSTEM_ALERT_WINDOW allow`（需系统权限）。

## 6. 版本限制与注意事项
- Android 11+：从开机广播后台直接启动“访问麦克风”的前台服务被禁止。
- Android 14/15：对 `BOOT_COMPLETED`/`LOCKED_BOOT_COMPLETED` 启动特定前台类型进一步收紧（麦克风、相机等），系统应用一般也不在常规豁免范围。
- 因此采用“分阶段启动”策略：开机只启 UI，解锁再启麦克风服务。

## 7. 验证步骤
- 构建与安装后，重启设备：
  - 观察 `BootBroadcastReceiver` 收到 `LOCKED_BOOT_COMPLETED`/`BOOT_COMPLETED` 日志；
  - 确认悬浮窗服务已前台运行并显示。
- 用户解锁：
  - 观察 `USER_PRESENT` 日志；
  - 验证 `WakeService` 自动拉起，麦克风正常工作。
- 权限校验：
  - `Settings.canDrawOverlays(context)` 为真；
  - `RECORD_AUDIO` 与通知权限已默认授予。

## 8. 常见问题与排查
- Manifest 解析错误：避免在标签属性区间插入注释，确保 XML 语法正确。
- `INSTALL_FAILED_SHARED_USER_INCOMPATIBLE`：平台签名与 `sharedUserId` 不一致，需卸载旧版重装。
- 悬浮窗不显示：AppOps 未允许，或接收器未导出/未触发（检查 action 与权限）。
- 开机拉起失败：服务仍标注麦克风类型或代码中指定麦克风前台类型，需移除。

## 9. 构建与部署建议
- 工作区构建验证脚本：执行仓库根目录 `run.sh`。
  - 当前脚本默认使用 `assembleHyundaiitDebug`；若产品不包含该变体，请将脚本改为 `./gradlew assembleDebug` 并调整 APK 路径。
- 系统集成流程：
  - 使用平台密钥重签；
  - 拷贝到 `/system/priv-app/com.ai.voice/`；
  - 配置 `privapp-permissions` 与默认权限授予；
  - 设置 AppOps `SYSTEM_ALERT_WINDOW` 为允许。
