**时机**: 应用启动时立即执行

**特点**:
- ✅ **后台异步验证**：不阻塞应用启动

- ✅ **容错处理**：验证失败不影响应用启动

**流程**:
```
App.onCreate()
    ↓
初始化 LicenseActivationManager
    ↓
后台协程启动
    ↓
调用 checkOnStartup()
    ↓
记录激活状态日志
```

**代码片段**:
```kotlin
// 后台验证激活状态（不阻塞启动）
applicationScope.launch {
    try {
        val activationManager = LicenseActivationManager.getInstance()
        val result = activationManager.checkOnStartup()
        if (result.activated) {
            Log.i(TAG, "✅ 设备已激活: fromCache=${result.fromCache}, fromMac=${result.fromMac}")
        } else {
            Log.w(TAG, "⚠️ 设备未激活: needLicense=${result.needLicense}, error=${result.error}")
        }
    } catch (e: Exception) {
        Log.e(TAG, "❌ 激活验证失败: ${e.message}", e)
    }
}
```

**时机**: 权限检查完成后，启动悬浮服务前

**特点**:

    ├─ 用户输入激活码
    ├─ 激活成功 → 保存状态 → 启动服务 ✅
    └─ 激活失败 → 显示错误提示 ❌

**代码片段**:
```kotlin
// 如果本地已激活，直接启动
if (activationManager.isActivated()) {
    Log.d(TAG, "✅ 设备已激活，启动服务")
    doStartService()
    return@launch
}

// 尝试通过MAC地址验证
val result = activationManager.checkOnStartup()

if (result.activated) {
    Log.d(TAG, "✅ MAC地址验证成功，启动服务")
    doStartService()
} else if (result.needLicense) {
    // 需要激活码，显示对话框
    Log.d(TAG, "⚠️ 需要激活码，显示激活对话框")
    showActivationDialog()
} else {
    // 验证失败，但允许继续使用（可选：可以阻止启动）
    Log.w(TAG, "⚠️ 激活验证失败: ${result.error}，允许继续使用")
    doStartService()
}
```

## 🔄 激活验证流程详解

### checkOnStartup() 完整流程

**位置**: `LicenseActivationManager.kt` 第 341-402 行

```
开始验证
    ↓
[步骤1] 检查本地激活状态
    ├─ SharedPreferences 中读取激活信息
    ├─ 检查激活标志 (activated)
    ├─ 检查过期时间 (expiresAt)
    ├─ 已激活且未过期 → 返回 ✅
    └─ 未激活或已过期 ↓
        
[步骤2] 获取MAC地址
    ├─ 方法1: NetworkInterface.getNetworkInterfaces()
    ├─ 方法1.1: 读取 /sys/class/net/wlan0/address
    ├─ 方法2: WifiManager.getConnectionInfo() (Android 6.0-)
    ├─ 方法3: Android ID (备用方案)
    ├─ 成功获取 ↓
    └─ 失败 → 返回错误 ❌
        
[步骤3] MAC地址服务器验证
    ├─ 请求: POST https://namingyou.com/api/licenses/verify-by-mac
    ├─ 参数: { appId, mac, name, deviceId }
    ├─ 超时设置: 10秒连接, 10秒读取
    ├─ 响应成功 ↓
    └─ 网络失败 → 返回错误 ❌
        
[响应处理]
    ├─ valid: true → 验证成功
    │   ├─ 保存激活状态到本地 (licenseKey, activatedAt, expiresAt)
    │   └─ 返回 ActivationResult(activated=true, fromMac=true) ✅
    │
    └─ valid: false → 验证失败
        └─ 返回 ActivationResult(needLicense=true) ⚠️
```

### 激活码激活流程

**位置**: `LicenseActivationManager.kt` 第 407-452 行

```
用户输入激活码
    ↓
[步骤1] 获取MAC地址
    ├─ 同上述方法
    └─ 失败 → 返回错误 ❌
        
[步骤2] 调用激活API
    ├─ 请求: POST https://namingyou.com/api/licenses/apply
    ├─ 参数: { licenseKey, appId, userInfo: { macAddress, ... } }
    ├─ 超时设置: 10秒连接, 10秒读取
    ├─ 响应成功 ↓
    └─ 网络失败 → 返回错误 ❌
        
[响应处理]
    ├─ success: true → 激活成功
    │   ├─ 保存激活状态到本地
    │   ├─ 关闭对话框
    │   └─ 启动服务 ✅
    │
    └─ success: false → 激活失败
        └─ 显示错误消息 ❌
```

## 🔐 MAC地址获取策略

### 多层级获取方案

#### 方法1: NetworkInterface (推荐) ✅
```kotlin
Collections.list(NetworkInterface.getNetworkInterfaces())
    .forEach { networkInterface ->
        val macBytes = networkInterface.hardwareAddress
        // 过滤无效MAC (02:00:00:00:00:00)
    }
```

**优点**:
- ✅ Android 6.0+ 仍然可用
- ✅ 不需要位置权限
- ✅ 获取真实网络接口MAC

#### 方法1.1: sysfs 文件系统 ✅
```kotlin
val paths = listOf(
    "/sys/class/net/wlan0/address",
    "/sys/class/net/eth0/address",
    "/sys/class/net/en0/address"
)
```

**优点**:
- ✅ 直接读取系统文件
- ✅ 不需要特殊权限
- ✅ 稳定可靠

#### 方法2: WifiManager (仅Android 6.0以下) ⚠️
```kotlin
val wifiManager = context.getSystemService(Context.WIFI_SERVICE)
val wifiInfo = wifiManager.connectionInfo
val mac = wifiInfo.macAddress
```

**限制**:
- ⚠️ Android 6.0+ 需要位置权限
- ⚠️ Android 10+ 返回随机化MAC

#### 方法3: Android ID (备用方案) 🔄
```kotlin
val androidId = Settings.Secure.getString(
    context.contentResolver,
    Settings.Secure.ANDROID_ID
)
```

**说明**:
- 🔄 不是真正的MAC地址
- ✅ 设备唯一标识符
- ✅ 应用复位后保持不变

## 🔧 故障排查指南

### 问题1: 无法获取MAC地址

**症状**: 日志显示 "无法获取MAC地址"

**可能原因**:
- Android 10+ 系统随机化MAC地址
- 权限不足
- 设备没有网络接口

**解决方案**:
1. 检查是否有网络连接
2. 使用Android ID作为备用方案（已实现）
3. 查看详细日志确定失败原因

### 问题2: MAC地址验证失败

**症状**: 日志显示 "MAC地址未在激活名单中"

**可能原因**:
- MAC地址未添加到服务器白名单
- MAC地址未通过激活码激活
- 网络请求失败

**解决方案**:
1. 将MAC地址添加到服务器白名单
2. 使用激活码激活设备
3. 检查网络连接和服务器状态

### 问题3: 网络请求超时

**症状**: 日志显示 "请求失败: timeout"

**可能原因**:
- 网络不稳定
- 服务器响应慢
- 防火墙阻止

**解决方案**:
1. 检查网络连接
2. 增加超时时间
3. 检查防火墙设置

### 问题4: 本地激活状态丢失

**症状**: 应用复位后需要重新激活

**可能原因**:
- SharedPreferences被清除
- 应用数据被清除
- MAC地址变化

**解决方案**:
1. MAC地址不变时可通过服务器验证恢复
2. 使用激活码重新激活
3. 考虑使用云端存储备份激活状态
