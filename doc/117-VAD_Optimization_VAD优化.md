# VAD 响应速度优化

## 问题

用户报告VAD检测延迟太长：
```
⏱️ [T1] 语音检测时间: 1673613820417ms (检测延迟: 4213ms)
```

检测延迟 **4.2秒** 太慢，用户体验很差。

## 原因分析

### 原配置（慢）
```kotlin
SileroVadModelConfig(
    threshold = 0.5f,              // 阈值较高，不够敏感
    minSilenceDuration = 0.25f,    // 需要250ms静音才判断语音结束
    minSpeechDuration = 0.25f,     // 需要250ms连续语音才触发检测 ❌
    windowSize = 512,              // 32ms窗口
    maxSpeechDuration = 5.0f       // 最多5秒语音
)
```

**核心问题：**
- `minSpeechDuration = 0.25f` 意味着VAD需要累积至少**250ms**的连续语音才会判定为"语音开始"
- 加上音频缓冲、处理延迟等，总延迟可能达到**300-500ms**甚至更多
- 如果用户说话声音较小或环境噪音，可能需要更长时间才能达到阈值

## 优化方案

### 新配置（快）✅
```kotlin
SileroVadModelConfig(
    threshold = 0.3f,              // 降低阈值：0.5 → 0.3 (提高敏感度)
    minSilenceDuration = 0.1f,     // 最小静音：0.25 → 0.1秒 (更快判断语音结束)
    minSpeechDuration = 0.05f,     // 最小语音：0.25 → 0.05秒 (更快触发) ✅
    windowSize = 512,              // 保持32ms窗口
    maxSpeechDuration = 10.0f      // 增加到10秒（支持更长语音）
)
```

### 优化效果预测

| 参数 | 原值 | 新值 | 改善 |
|------|------|------|------|
| **threshold** | 0.5 | 0.3 | 降低40%，更容易触发 |
| **minSpeechDuration** | 0.25秒 | 0.05秒 | **减少80%延迟** ⚡ |
| **minSilenceDuration** | 0.25秒 | 0.1秒 | 减少60%结束判断时间 |
| **maxSpeechDuration** | 5秒 | 10秒 | 支持更长的连续语音 |

**预期检测延迟：**
- **原来：** 250ms (minSpeechDuration) + 缓冲延迟 ≈ **300-500ms**
- **优化后：** 50ms (minSpeechDuration) + 缓冲延迟 ≈ **100-200ms** ⚡
- **改善幅度：** **60-75%** 🚀

## 参数说明

### threshold（检测阈值）
- **范围：** 0.0 - 1.0
- **原值：** 0.5（较保守）
- **新值：** 0.3（更敏感）
- **影响：** 值越小越敏感，但可能误触发
- **权衡：** 0.3是一个平衡点，既敏感又不会频繁误触发

### minSpeechDuration（最小语音持续时间）
- **原值：** 0.25秒（保守）
- **新值：** 0.05秒（激进）✅
- **影响：** 这是**最关键**的参数！
  - 250ms → 50ms，减少**200ms**延迟
  - 用户感知：从"反应慢"到"即刻响应"
- **风险：** 可能会将极短的噪音误判为语音
- **缓解：** 通过threshold=0.3平衡，避免噪音误触发

### minSilenceDuration（最小静音持续时间）
- **原值：** 0.25秒
- **新值：** 0.1秒
- **影响：** 判断语音结束的速度
  - 用户停顿100ms后就判断语音结束
  - 更快进入最终识别阶段
- **风险：** 短暂停顿（如"嗯..."）可能被切断
- **权衡：** 0.1秒是合理值，足够区分停顿和结束

### maxSpeechDuration（最大语音持续时间）
- **原值：** 5秒
- **新值：** 10秒
- **影响：** 支持更长的语音输入
  - 适合长句子、复杂命令
  - 避免长语音被截断

## 副作用和权衡

### 可能的问题

#### 1. 误触发增加
- **症状：** 背景噪音被误判为语音
- **解决：** 微调threshold（0.3 → 0.35）

#### 2. 语音被切断
- **症状：** 说话停顿后被截断
- **解决：** 增加minSilenceDuration（0.1 → 0.15）

#### 3. CPU占用增加
- **症状：** 设备发热
- **解决：** 使用节能模式或降低采样率

### 推荐配置组合

#### 快速响应（推荐）✅
```kotlin
threshold = 0.3f
minSpeechDuration = 0.05f
minSilenceDuration = 0.1f
```
**适用：** 大多数场景，平衡速度和准确性

#### 超快响应（实验性）
```kotlin
threshold = 0.25f
minSpeechDuration = 0.03f
minSilenceDuration = 0.08f
```
**适用：** 需要极低延迟的场景
**风险：** 误触发率可能偏高

#### 保守配置（原配置）
```kotlin
threshold = 0.5f
minSpeechDuration = 0.25f
minSilenceDuration = 0.25f
```
**适用：** 需要极高准确性，可容忍延迟
