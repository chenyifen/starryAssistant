## 音频回放端到端测试方案（离线唤醒 + 命令识别）

### 目标
在无需使用真实麦克风的情况下，使用预先录制的“唤醒音频 + 命令音频”模拟实时输入，验证整条链路是否正常：
- 唤醒是否被正确触发
- 唤醒后 ASR 是否能准确识别命令
- 文本识别结果与预期命令匹配是否正确
- 关键时序与稳定性（触发时延、识别耗时等）

### 前置与约束
- 音频格式：优先 16 kHz、单声道、PCM16（.wav 或裸 .pcm）。如不是 16 kHz，需重采样到 16 kHz。
- 唤醒框架：使用 `WakeDeviceWrapper`（按当前配置构建具体唤醒设备）。
- ASR 输入：通过新增 `FileReplayInputDevice`（实现 `SttInputDevice`）用文件替代 `AudioRecord`。
- 回放策略：默认“实时速率”（按帧 sleep），支持“加速倍速”以缩短测试时间。
- 资源仲裁：若 TTS 播放占用音频资源，ASR 文件回放需等待/暂停，保持与线上一致的行为。

### 目录与文件组织建议
- 测试数据目录：`testdata/`
  - 唤醒音频：`testdata/wake/*.wav`
  - 命令音频：`testdata/cmd/*.wav`
  - 批量清单：`testdata/plan.json` 或 `testdata/plan.yaml`
- 报告输出：`reports/`
  - 单次唤醒报告：`reports/wake_{timestamp}.json`
  - 单次端到端报告：`reports/e2e_{caseId}_{timestamp}.json`
  - 汇总报告：`reports/e2e_summary_{timestamp}.json` 与可读版 `reports/e2e_summary_{timestamp}.md`

### 待办清单（含输入/输出交付与实现类方法）

#### 1) 基础 PCM/WAV 读取与帧化（FilePcmReader + PcmFrameStreamer）
- 输入：
  - 文件路径（.wav 或 .pcm）
  - 目标采样率（默认 16000）
  - 帧尺寸/帧时长（唤醒用 `wake.frameSize()`；ASR默认100ms=1600样本@16k）
  - 回放倍速（1.0=实时，>1.0 加速）
  - 可选偏移（起止时间，去头去尾静音）
- 输出交付：
  - 可迭代/Flow/Channel 的帧流：`ShortArray`（唤醒用）、`FloatArray`（ASR用，归一化到[-1,1]）
  - 统计信息（样本数、时长、峰值、RMS、零交叉率等）供日志与质量判断
- 需实现的类/方法：
  - `com.ai.voice.testing.audio.FilePcmReader`
    - `fun readAllShorts(file: File): ShortArray`
    - `fun inferSampleRate(file: File): Int`（WAV 头解析；裸 PCM 通过参数或默认）
    - `fun ensureMono16k(input: ShortArray, srcRate: Int): ShortArray`（必要时重采样/下混音）
  - `com.ai.voice.testing.audio.PcmFrameStreamer`
    - `fun streamShortFrames(samples: ShortArray, sampleRate: Int, frameSize: Int, speed: Float): Flow<ShortArray>`
    - `fun toFloatFrames(frames: Flow<ShortArray>): Flow<FloatArray>`（/32768f 归一化）

#### 2) 唤醒重放 Runner（WakeReplayRunner）
- 输入：
  - `WakeDeviceWrapper` 实例
  - 唤醒音频文件路径
  - 可选参数：倍速、重复次数、最大触发时延阈值(ms)
- 输出交付：
  - 布尔：是否触发
  - 数值：触发时延(ms)、总耗时(ms)
  - JSON 报告：`reports/wake_{timestamp}.json`（含设备类型、frameSize、统计、失败原因）
- 需实现的类/方法：
  - `com.ai.voice.testing.wake.WakeReplayRunner`
    - `suspend fun run(wakeFile: File, wrapper: WakeDeviceWrapper, config: WakeReplayConfig): WakeReplayResult`
    - 内部：`feedFramesToWakeDevice(frames: Flow<ShortArray>): Boolean`（逐帧调用 `wrapper.processFrame(frame)`）

#### 3) ASR 文件回放输入设备（FileReplayInputDevice : SttInputDevice）
- 输入：
  - 命令音频文件路径
  - 事件回调 `(InputEvent) -> Unit`
  - 回放参数：倍速、最大录音时长、静音超时
- 输出交付：
  - `uiState: StateFlow<SttState>`（NotInitialized/Loaded/Listening/...）
  - `InputEvent.Partial`、`InputEvent.Final` 回调，与现有设备一致
  - 识别文本、耗时统计日志
- 需实现的类/方法：
  - `com.ai.voice.io.input.file_replay.FileReplayInputDevice : SttInputDevice`
    - `override fun tryLoad(thenStartListeningEventListener: ((InputEvent) -> Unit)?): Boolean`
    - `override fun onClick(eventListener: (InputEvent) -> Unit)`（复用 `tryLoad/stop` 语义）
    - `override fun stopListening()`、`override suspend fun destroy()`
    - 内部：`recordFromFile()`（替换 `AudioRecord`，从帧流推送到 `samplesChannel`）
    - 内部：`processAudio()`（可复用 `SherpaOnnxSimulateInputDevice` 的 VAD+200ms 识别流程）

#### 4) 端到端编排器（EndToEndReplayTestRunner）
- 输入：
  - 唤醒音频文件、命令音频文件
  - 预期结果：期望文本（或正则）、期望意图/命令校验函数
  - 参数：各阶段超时/阈值、倍速
- 输出交付：
  - 单次端到端 JSON 报告：包含唤醒结果与时延、ASR 最终文本、匹配结果、关键耗时、失败原因
  - 可选：Markdown 可读版报告片段
- 需实现的类/方法：
  - `com.ai.voice.testing.e2e.EndToEndReplayTestRunner`
    - `suspend fun run(wakeFile: File, cmdFile: File, expectation: Expectation): E2EReplayResult`
    - 内部：`waitWakeThenStartAsr()`（监听 `WakeDeviceWrapper.state/isHeyDicio` 或 `processFrame` 返回）
    - 内部：`collectAsrEvents()`（汇聚 Partial/Final，并做期望匹配）

#### 5) 批量测试与汇总报告（ReplayBatchRunner）
- 输入：
  - 测试清单 `plan.json`/`plan.yaml`（每项含：`id`, `wake`, `cmd`, `expected_text`/`expected_regex`/`expected_intent`）
  - 全局参数：倍速、阈值
- 输出交付：
  - 单例报告若干 + 汇总报告（JSON + Markdown），统计成功率、均值/分位耗时、失败Top原因
- 需实现的类/方法：
  - `com.ai.voice.testing.batch.ReplayBatchRunner`
    - `suspend fun runAll(planFile: File, global: GlobalConfig): BatchSummary`
    - 生成：`reports/e2e_summary_{timestamp}.json` 与 `reports/e2e_summary_{timestamp}.md`

#### 6) 开关与入口（开发者设置或 Intent）
- 输入：
  - 开发者设置：启用“文件回放测试模式”、指定 `testdata` 目录
  - 或 ADB/调试页面：发送 `Intent` 触发单次/批量测试
- 输出交付：
  - UI 或命令入口；切换后 `SttInputDeviceWrapper` 在测试时强制使用 `FileReplayInputDevice`
- 建议实现：
  - 在 `SttInputDeviceWrapper` 读取一个“测试模式”标志（本地 DataStore 或 BuildConfig），为真时返回 `FileReplayInputDevice`
  - 或新增 `BroadcastReceiver`：`EndToEndReplayReceiver` 接收 `ACTION_RUN_E2E_REPLAY`，参数为文件路径/计划路径

#### 7) 测试数据规范与样例
- 输入：
  - 设计规范文档 + 样例音频若干
- 输出交付：
  - `testdata/README.md`：
    - 命名建议：`{lang}_{wakeId}_{caseId}.wav`（例如：`zh_hey_dicio_001.wav`）
    - 采样：16k/mono/PCM16；头尾静音≤300ms；峰值<0.95，RMS>0.001
    - 批量计划文件字段定义与样例
- 需实现的文件：
  - `testdata/README.md`
  - `testdata/plan.sample.json`

### 校验与指标（验收标准）
- 唤醒：
  - 触发成功率 ≥ 99%（同设备同模型）
  - 触发时延：P50 ≤ 500ms，P95 ≤ 800ms（示例阈值，可按设备调整）
- ASR：
  - 文本匹配：支持精确匹配或正则匹配
  - 失败分类：空文本、低能量、剪切、模型未加载、资源被占用
- 稳定性：
  - 重放倍速 ≥ 4x 时不崩溃；资源释放正确；日志完整

### 日志与可观测性
- 统一 Tag：
  - Wake：`WakeReplay`
  - ASR 文件回放：`FileReplayASR`
  - E2E：`E2EReplay`
- 关键点打印：
  - 帧统计（每N帧）
  - 触发/识别时间戳（T0录制起、T1检测到语音、T2部分结果、T3最终结果）
  - 音频质量统计（RMS/Peak/ZeroCrossingRate）

### 快速使用（完成后）
- 单次：
  - 方式A（调试页）：选择唤醒与命令文件，点击“运行回放测试”
  - 方式B（ADB）：发送 `adb shell am broadcast -a com.ai.voice.ACTION_RUN_E2E_REPLAY --es wake /sdcard/testdata/wake/zh_hey.wav --es cmd /sdcard/testdata/cmd/zh_open_news.wav`
- 批量：
  - `adb shell am broadcast -a com.ai.voice.ACTION_RUN_E2E_REPLAY --es plan /sdcard/testdata/plan.json`

以上方案与待办可在不改动现有业务路径的前提下，完整模拟“麦克风→唤醒→ASR→命令”的链路，适合持续集成或设备回归测试场景。
