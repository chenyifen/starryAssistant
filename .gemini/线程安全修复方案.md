# 线程安全和状态卡死问题 - 简单修复方案

## 📋 修复时间
2025-12-05 16:14

## ✅ 已完成的修复

### 1. AsrHandler 线程安全修复 🔴

**问题**: `isStarted` 和回调变量不是线程安全的

**修复**: 添加 `@Volatile` 和 `@Synchronized`

**代码位置**: `AsrHandler.kt`

```kotlin
// 修复前
private var isStarted = false
private var silenceTimeoutCallback: (() -> Unit)? = null
private var finalResultCallback: ((String) -> Unit)? = null

fun start(context: Context): Boolean {
    if (isStarted) return true
    isStarted = true
    // ...
}

fun stop(context: Context) {
    isStarted = false
    // ...
}
```

```kotlin
// 修复后
// 🔒 线程安全：使用 @Volatile 确保多线程可见性
@Volatile
private var isStarted = false

// 🔒 线程安全：回调变量使用 @Volatile
@Volatile
private var silenceTimeoutCallback: (() -> Unit)? = null

@Volatile
private var finalResultCallback: ((String) -> Unit)? = null

// 🔒 线程安全：使用 synchronized 防止竞态条件
@Synchronized
fun start(context: Context): Boolean {
    if (isStarted) {
        Log.d(TAG, "⏭️ AsrHandler 已经在运行中")
        return true
    }
    isStarted = true
    // ...
}

@Synchronized
fun stop(context: Context) {
    if (!isStarted) {
        Log.d(TAG, "⏭️ AsrHandler 已经停止")
        return
    }
    isStarted = false
    // ...
}
```

**效果**:
- ✅ 防止多线程同时调用 `start()` 或 `stop()`
- ✅ 确保 `isStarted` 的修改对所有线程立即可见
- ✅ 防止回调在设置时被并发调用

### 2. 移除 SPEAKING 和 ERROR 状态 🟡

**问题**: 状态过于复杂，增加卡死风险

**修复**: 简化为只有 IDLE 和 LISTENING 两种状态

**代码位置**: `VoiceAssistantStateProvider.kt` 第 288-421 行

```kotlin
// 修复后：只有两种状态
when (normalizedTargetState) {
    VoiceAssistantUIState.IDLE -> {
        // 停止 ASR + 启动 Wake
    }
    
    VoiceAssistantUIState.LISTENING -> {
        // 启动 ASR + Wake 自动暂停
    }
    
    else -> {
        // 未知状态默认转换为 IDLE
        transitionToState(VoiceAssistantUIState.IDLE, ...)
    }
}

// SPEAKING 和 ERROR 自动转换为 IDLE
val normalizedTargetState = when (targetState) {
    VoiceAssistantUIState.ERROR,
    VoiceAssistantUIState.SPEAKING -> VoiceAssistantUIState.IDLE
    else -> targetState
}
```

**效果**:
- ✅ 状态转换更简单
- ✅ 减少卡死风险
- ✅ TTS 播放期间保持 LISTENING 状态

### 3. Fallback 技能也触发状态转换 🟢

**问题**: Fallback 技能 (skillId == "text") 不触发状态转换，可能导致卡在 LISTENING

**修复**: 所有技能执行完成后都转换到 IDLE

**代码位置**: `EnhancedFloatingWindowService.kt` 第 300-326 行

```kotlin
// 修复前
if (lastAnswer != null && skillId != "text") {
    transitionToState(IDLE, ...)  // Fallback 技能不触发
} else if (lastAnswer != null && skillId == "text") {
    // 不更新状态 ❌ 可能卡死
}
```

```kotlin
// 修复后
// 🔥 简化：所有技能执行完成后都转换到 IDLE（包括 Fallback）
if (lastAnswer != null) {
    serviceScope.launch {
        transitionToState(IDLE, reason = "技能执行完成: $skillId")
    }
}
```

**效果**:
- ✅ 防止 Fallback 技能导致状态卡死
- ✅ 确保所有技能执行后都能恢复到 IDLE

## 📊 状态转换流程（修复后）

### 完整流程

```
IDLE (Wake运行, ASR停止)
  ↓ (1) 唤醒词检测
LISTENING (Wake暂停, ASR运行)
  ↓
  ├─ (2a) 静音超时 (10秒) → IDLE
  ├─ (2b) 技能执行完成 → IDLE
  ├─ (2c) TTS播放完成 + ASR未运行 → IDLE
  └─ (2d) 错误 → IDLE (自动转换)
```

### 触发点总结

**IDLE → LISTENING (1个触发点)**:
1. ✅ 唤醒词检测

**LISTENING → IDLE (3个主要触发点)**:
1. ✅ 静音超时 (10秒)
2. ✅ 技能执行完成（包括 Fallback）
3. ✅ TTS播放完成 + ASR未运行

## ⚠️ 剩余风险（已大幅降低）

### 低风险场景

1. **TTS 永不结束** ⚠️ 低
   - **现象**: TTS 服务卡住
   - **影响**: 状态可能保持 LISTENING
   - **缓解**: 静音超时机制仍然有效（10秒后自动恢复）
   - **建议**: 未来可添加 TTS 超时保护（30秒）

2. **极端环境噪音** ⚠️ 低
   - **现象**: 持续背景噪音，VAD 一直检测到"语音"
   - **影响**: 静音超时可能不触发
   - **缓解**: 技能执行完成仍会触发状态转换
   - **建议**: 未来可添加绝对超时（60秒强制返回 IDLE）
