## ⚠️ 发现的问题

### 问题 1: WakeService 在 ASR 运行时的暂停机制

**位置**: `WakeService.kt` 第 533-564 行

**现状**:
```kotlin
if (com.ai.voice.util.AsrHandler.isStarted()) {
    // 暂停 AudioRecord
    ar.stop()
    // 等待 AsrHandler 停止
    while (com.ai.voice.util.AsrHandler.isStarted() && listening.get()) {
        Thread.sleep(100)
    }
    // 重新启动AudioRecord
    ar.startRecording()
}
```

**问题**: WakeService 会暂停唤醒检测，等待 ASR 停止后才恢复

**音频资源冲突**: 
- ✅ **已解决**: WakeService 在检测到 AsrHandler 运行时会主动暂停
- ✅ **已解决**: AsrHandler 停止后，WakeService 自动恢复

### 问题 2: ⚠️ **UI状态与实际音频资源不一致**

**场景 A**: TTS 播放完成，ASR 未运行

**修复前**:
```kotlin
// setupTTSCompletionCallback()
updateState(uiState = VoiceAssistantUIState.IDLE, ttsText = "", displayText = "")
// ❌ 问题：设置 IDLE 但没有确保 ASR 停止和 Wake 启动
```

**修复后**:

**修复后**:

### 问题 3: ⚠️ **observeSkillEvaluation 中的状态更新**

**位置**: `EnhancedFloatingWindowService.kt` 第 291-311 行

```kotlin
private fun observeSkillEvaluation() {
    if (lastAnswer != null && skillId != "text") {
        // ❌ 问题：只更新UI状态，不处理ASR和Wake
        voiceAssistantStateProvider.updateUIState(VoiceAssistantUIState.IDLE)
        // 注释说明: "这里不会调用AsrHandler.stop()，让ASR自然超时停止"
    }
}
```

**分析**:
- ❌ **不一致**: UI 已设置为 IDLE，但 ASR 可能仍在运行
- ❌ **不一致**: UI 显示 IDLE，但实际还在监听语音
- ⚠️ **可能问题**: 依赖 ASR 自然超时（4秒），期间用户无法再次唤醒

**建议修复**:
这个位置也应该停止 ASR 并启动 Wake，确保状态一致性。
